# 親指シフトタイピング道場

> 速さより先に、ズレを直す。

親指シフト（NICOLA配列）の練習。**文字キーと親指キーの押下が何ミリ秒ずれたかを1打ごとに測り、
先行しているのか遅れているのかを返します。**

<https://kanade0525.github.io/oyayubi-dojo/>

---

## なぜ作ったか

親指シフトの練習サイトは、検索して上位に出るのが
[親指タイピング](https://oyayubi-typing.solaniwa.net/) ほぼ一つで、**2021年8月で更新が止まっています。**

そのサイトのソースを読むと、同時打鍵の判定はこうなっていました。

```js
// 文字キーの keydown から 30ms 待って、その時点で親指フラグが立っていればシフト面
setTimeout(() => {
  const shift = thumbL_isShift ? "left" : thumbR_isShift ? "right" : "noshift";
}, headMargin);
```

**打鍵時刻を一切測っていません。** 運営自身も「エミュレーターソフトほど厳密なものではない」と
明記しています。localStorage に入るのは設定だけで、スコアは保存されず、閉じたら消えます。

一方で富士通は2020年に撤退し、キーボードも Japanist 10 も2021年に販売終了、
**公式サポートは2026年6月に終了**しました。公式の受け皿が消え、コミュニティのOSSしか残っていません。

## 何が違うか

**同時打鍵は、本質的にタイミングの技能です。** 既存ツールは時間差を測っていないので、
上達しているかが本人に見えません。この道場は `performance.now()` で押下時刻を取り、
時間差をリズムゲームの判定として返します。

| 判定 | 時間差 |
| --- | --- |
| ぴったり | ±15ms 以内 |
| 良い | ±35ms 以内 |
| ずれ | それ以上。**先行か遅れかを必ず出す** |
| 不発 | シフトが効かず単打になった。打ち直し |

**向きを出すのが肝です。** 親指が遅い人と早すぎる人では直し方が逆なので、
向きが分からないと直せません。ここが既存ツールに無い情報です。

音でも返します。**親指が先行なら低→高、遅れなら高→低**に鳴り、ぴったり合うと二つが融けて
一つの音になります。画面を見ずに、耳だけで向きが分かります。

## 二つの入口

**違いはひとつだけ。覚えるは「まだ打てない字」を、鍛えるは「もう打てる字」を扱います。**

| | |
| --- | --- |
| **覚える** | 配列を順に。単独打鍵から濁音・交差シフトまで、七つの課・46題を決まった道筋で |
| **鍛える** | 順番なし。落としている面とズレの大きいキーだけを、そのつど組んで出す |

記録（段位・ズレの分布・苦手な面・実績）は打てば自動的に貯まります。

## 回転ずし（ゲーム）

`game.html`。流れてくる皿の単語を親指シフトで打ち切ると皿が取れます。制限時間内にコースの値段より多く取れば得。
同時打鍵が **ぴったり（±15ms）** なら皿の値段が上がるので、ここでもズレを詰めることが得点になります。
ランキングは任意参加です（下の「外に出ていかない」）。サーバー側は `server/`（AWS SAM）にあります。

## 打つ前に

1. **日本語入力（IME）を OFF** にしてください。ON だとキーがこのページに届く前に
   OS が文字を作ってしまい、押下の時間差が測れません
2. **親指シフトのエミュレータ（やまぶき・DvorakJ・Karabiner の NICOLA 設定など）は止めてください。**
   この道場は自前で同時打鍵を判定するので、二重に効いて壊れます

親指キーの既定は **英数（`Lang2`・スペースの左）** と **かな（`Lang1`・スペースの右）** です。
macOS の JIS キーボードで実測し、押下も解放も取れて IME に横取りされないことを確認しています。
Windows の 無変換／変換 も同じ位置です。別のキーにも割り当てられます（設定画面）。

うまく取れない環境では `keycheck.html` を開くと、押したキーの生のイベントがそのまま見られます。

## 手元で動かす

```
npm run dev     # 依存ゼロの静的サーバー。_headers も同じように付く
npm test        # 同時打鍵の状態機械と適応出題の単体テスト
npm run check   # 総合検査（下記）
```

**依存パッケージは一つもありません。** `npm install` は不要です。

## 検査

`npm run check` は依存ゼロの自作検査です。Chrome を起動して DevTools Protocol を直に叩きます。

- 配列データの検算（**交差シフト＝濁音、同側シフト＝別のかな** の規則が守られているか）
- 単体テストの実行（TAP を読み、一本も拾えていなければ落とす）
- 全配色 × 全組み合わせのコントラスト比を実測
- CSP が壊れていないか／効いているか（外へ fetch して違反イベントの発火で確認）
- 画面ごとに「JS が入れるはずの中身」が出ているか
- `CONTRACT.md` の担当表・契約と、実装の双方向の突き合わせ

**検査の検査もします。** わざと壊した入力を毎回流し、必ず所見が出ることを確かめます。
これが空振りしていると、検査は「所見ゼロ」を返し続けて緑になるためです。

## 外に出ていかない（ランキングに参加しない限り）

練習の記録はこの端末の `localStorage` の中だけにあります。どこにも送信しません。

例外はゲーム「回転ずし」（`game.html`）のランキングだけです。**参加は任意で、同意したときだけ**
ニックネームとゲームのスコアを送ります。メールアドレスや本名は取りません。練習の記録は送りません。
「自分の記録を消す」でサーバー側の記録も消えます。

`_headers` の `connect-src` は `'none'` か、**ランキング API のオリジンちょうど一つ**のどちらかに限っています。
README にそう書くだけでは宣言に留まりますが、これを置くと**うっかり CDN の URL を書いた時点でブラウザが止めます**。
宣言が不変条件になります。`npm run check` が `assets/js/game/config.js` と `_headers` を突き合わせます。
配列表を JSON ではなく JS モジュールにしてあるのは、`fetch` を一つも使わずに済ませるためです。

## 構成

```
index.html            画面の骨格（5つの section を hidden で切り替え）
keycheck.html         キー実測ページ（単体で動く）
game.html             ゲーム「回転ずし」
assets/
  img/                アイコン（弓道の霞的。輪の比率は実寸どおり）
  data/nicola.js      NICOLA配列表
  js/
    nicola.js         同時打鍵の状態機械（DOMを知らない）★中核
    layout.js         配列の引き当て
    engine.js         課題の進行と正誤判定
    drill.js          適応出題
    storage.js        localStorage
    trophies.js       段位・実績・アンロック
    lessons.js        課題データ
    meter.js          タイミングメーター
    keyboard.js       3面キーボード図
    sound.js          WebAudio による打鍵音の合成
    app.js            配線
  js/game/            ゲーム（engine.js は DOM を知らない状態機械。ranking.js がランキングの窓口）
tools/check.mjs       総合検査
server/               ランキングの API（Lambda + DynamoDB、AWS SAM）
docs/game-design.md   ゲームの数値の根拠
CONTRACT.md           モジュール間の契約と、言葉の決め方
```

`nicola.js` は **NICOLA規格 JIS提案 §5.4「同時打けんの判定」** の状態機械をそのまま実装しています
（5状態 S1〜S5、処理A〜D）。**規格の状態遷移表は2018年4月に修正されている**ので、
古い版を実装すると同時打鍵が全部二重出力になります。
